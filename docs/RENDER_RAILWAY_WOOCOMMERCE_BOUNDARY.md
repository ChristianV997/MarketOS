# Render / Railway / WooCommerce integration boundary

This is a **boundary document**, not a second storefront or workflow engine.

## Surfaces

| Surface | Role | Default |
|---------|------|---------|
| MarketOS private API (Railway or Render) | FastAPI `/health` `/ready` JSONL/fixture path | Simulated / fixture |
| Operator frontend (Vercel or local Vite) | Read-only dashboards + cockpit | `VITE_API_BASE_URL` only |
| Storefront (WooCommerce / Shopify / Medusa) | Customer catalog & checkout | **Manual** — MarketOS drafts stay `status: draft` |
| Supplier portal (CJ / Ali / CSV imports) | Evidence import | Fixture or manual CSV; live probe needs credentials + approval |
| Payments (Stripe / Mercado Pago) | Charge capture | **Blocked** — no operator command enables it |
| Analytics (PostHog) | Optional public key in frontend | Manual; no authority |
| Support (Chatwoot etc.) | Messaging | **Blocked** — not in this workflow |

Use **either** Railway **or** Render for the first MVP API, not both
(`deploy/railway/README.md`, `deploy/render/README.md`).

## Classification

| Question | Answer |
|----------|--------|
| What remains manual? | Credential entry, Approval Ledger policy, live supplier probe, storefront publish, DNS/TLS |
| What is simulated? | Unit economics assumptions, commerce MVP slice, scenario pack, supplier CSV copy |
| What requires credentials? | CJ read-only probe, Supabase staging, any future DataForSEO/SerpApi adapter |
| What requires human approval? | Anything leaving fixture mode; public-run gate; provider activation |
| What cannot run on free-tier? | Crawl4AI JS render farms, always-on workers, queues, multi-region storefronts |
| Where are reports stored? | Operator-chosen safe `--output` directory (never `artifacts/` from this wrapper) |
| How to roll back? | Redeploy previous Railway/Render revision; unset live env flags; revert frontend `VITE_API_BASE_URL` |

## Forbidden

- Second Medusa/Woo storefront generated by this operator pack
- Enabling orders, ads, inventory mutation, or customer messages from PowerShell
- Treating Netlify/Vercel preview badges as API health
